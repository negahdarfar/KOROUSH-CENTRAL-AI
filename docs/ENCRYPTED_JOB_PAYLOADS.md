# Encrypted job payload storage

## Design
- Payloads are JSON-serialized and encrypted with Fernet authenticated encryption before any database write.
- The SQLite row contains ciphertext only, with an opaque UUID reference and expiry timestamps.
- Payload size is capped at 64 KiB; TTL is bounded from 60 seconds to 7 days.
- The worker resolves the opaque reference only after revalidating the tenant key and team/repository binding. The handler receives decrypted payload data, not the storage reference.
- Missing/invalid encryption key, missing payload, expiry or authentication failure stops execution; it is not silently treated as an empty payload.
- Expired rows can be pruned in bounded batches.

## Required secret
Set `JOB_PAYLOAD_ENCRYPTION_KEY` to a Fernet URL-safe base64 key generated by the Python `cryptography` package. Keep it outside source control and never store it in SQLite. Losing or rotating this key without an explicit re-encryption migration makes existing ciphertext unreadable. Back up the key separately from the database and restrict access.

## Production limits
This is encrypted-at-rest storage in the same SQLite database/volume as job metadata; it is not a separate KMS or isolated secrets vault. Database backups still contain ciphertext and must be protected. The single-host SQLite deployment model remains. No worker process, Railway variable, secret, volume or deployment is activated by this PR.
